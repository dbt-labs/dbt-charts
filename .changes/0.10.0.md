## 0.10.0 (2026-10-19)
### Breaking changes
- Board markdown images (`text:` blocks, titles, tab text, callouts) now resolve against the project and embed in the render instead of being left for the viewer to resolve. A relative path resolves beside the file it is written in; a path starting with `/` resolves from `charts/`. A `charts/`-rooted path written without the `/` (`assets/logo.png` from `charts/cards/`) is not migrated: add the `/`. A template can no longer build a project image path. An image that does not resolve renders as error text and reports `ERR-IMAGE-REF-UNRESOLVED`, so `dct render` exits non-zero unless `--allow-chart-errors` is passed. Board artifacts written by earlier releases no longer load.
- A chart's `number_format` and `time_format` move to the axis label format; boards update automatically unless the target slot already has a format, which needs a manual move. A query's `formats:` now sets a column's format everywhere.
- The validate_board, query_board, search_skills and describe_query agent tools are removed, along with dct query --describe and dct skills --search: render_board validates, execute_sql takes board and query to run a stored board's named query, and list_skills lists the skills.
- dct query no longer takes --limit and prints CSV capped by a byte budget; --json returns up to 1,000 rows.
- Trino sources no longer use dbt-trino: TLS certificates are verified unless `cert: false` is set, and a profile target with `keytab:` or an unknown key is an error.
- dbt Charts now requires Python 3.11 or newer.
- A date-only `label.values` entry with a trailing `Z`, such as `2024-01-01Z`, now raises an invalid-date error instead of parsing.
- `dct cloud project connect` now takes the git host first (`github`, `gitlab`, `bitbucket` or `git`) in place of the bare `--git-url` and `--start` forms; `git` takes `--git-username` and `--git-password` for a private repo.
- The `search_boards`, `glob_files` and `grep_files` tools are replaced by one `search_files` tool (use `kind` to search meta, models and config files).
- The MCP tool `execute_query` is now `execute_sql`; it returns CSV bounded at 25,000 tokens and no longer takes a `limit` argument.
### Features
- Every number format slot accepts a `FormatConfig` with `prefix`, `suffix` and `notation`, inline or as a `style.formats` alias, so non-dollar currencies (`€500`, `EUR 500`) paint everywhere, hover cards included. `sign_placement` and `repeat` control where the sign sits and whether the affix appears on every value or once per axis, column or row. [Closes dbt-labs/dbt-charts#27](https://github.com/dbt-labs/dbt-charts/issues/27)
- Added a `databricks` source type: `type: databricks` with `host`, `http_path`, `catalog`, an optional `schema`, and either a personal access `token` or an OAuth service principal (client ID and secret). `http_path` must name a SQL warehouse (`/sql/1.0/warehouses/<id>`), and `connect_timeout` bounds how long a connection retries while the warehouse starts.
- A new render warning, WARN-SERIES-LABELS-REPEAT-WORD, fires when every series label of a multi-series chart repeats the same leading or trailing word -- e.g. "Documents Created" / "Documents Completed" instead of "Created" / "Completed". Its fix says to drop the word when the title or `y_label` already states it, and to move it there otherwise.
- `dct cloud status` works before login: it reports this checkout, the linked org and project, and the setup steps still needed.
- Markdown images now render inline: mid-sentence, in a heading, a list item, or a table cell, instead of as alt text, and an inline image takes the same `{width=X height=Y}` size shorthand a standalone image does. A line holding an image taller than its text grows to fit it, and multi-column text packs each column by its lines' own heights. An embedded `data:` image sizes at its own aspect ratio instead of 16:9. A render never fetches a remote image, a board title's included.
- Charts accept `field_labels:`, display text per column for legends, tooltips and axis titles. Derived labels keep mixed-case words such as `MTok` instead of lowercasing them.
- Table charts accept a chart-root `spanners:` list that draws a label over a run of adjacent columns, so a shared category is written once instead of in every column label.
- `legend.position` is now a mapping of `edge` (`left`, `right`, `top`, `bottom`), `align` (`start`, `center`, `end`) and `overlay` (float over the plot or reserve a strip), so a legend can be centered along its edge and whether it covers data is explicit. Without an authored `direction`, `top` and `bottom` legends lay out horizontally and `left` and `right` vertically, so a `top` legend hides its title unless `title.visible: true`. A pie or donut takes `edge` and `align` only.
- Named fonts: define fonts once under `style.fonts` and use them in any `font:` by name (`font: heading`) or with overrides, including table text, footers and timestamps. An entry can `extends:` another and override its keys. Table cells follow `fonts.label`, no longer `style.font.size`. Heading sizes move from `style.title.sizes` to `style.fonts.heading.sizes`; boards update automatically.
- `dct doctor` diagnoses why `dct` can't reach your data: it reports how dbt Charts was installed, which Python runs it, whether the project and `profiles.yml` were found, and, for each source in `dbt_charts.yml`, whether its warehouse adapter is installed. Add `--with-warehouse` to also connect to each source, and `--json` for a report you can paste into a ticket. Exits 1 when any check fails.
- A `dbt_profile` source can set `target_path:` to the directory holding the manifest built for its target (`dbt parse --target prod --target-path target/prod`), so `ref()` and `source()` resolve against that target instead of whichever manifest `target/` last held. Without it, the manifest location now follows dbt: `DBT_TARGET_PATH`, then `dbt_project.yml` `target-path:`, then `target`. [Closes dbt-labs/dbt-charts#9](https://github.com/dbt-labs/dbt-charts/issues/9)
- dbt Charts can now connect to SQL Server. Install `dbt-charts[sqlserver]` and point a source at a SQL Server target through `type: dbt_profile`. `max_query_duration_seconds` is enforced through the profile's `query_timeout`, and dbt-sqlserver's warnings go to stderr so `--json` output stays valid. The host needs Microsoft ODBC Driver 17 or 18. [Closes dbt-labs/dbt-charts#53](https://github.com/dbt-labs/dbt-charts/issues/53)
- `dct render --format thumbnail` produces an abstracted board thumbnail: an SVG of the same size with every piece of text replaced by a placeholder, axes and legends removed, and tables redrawn as per-column blocks and value bars.
- Board `text:`, board titles, and chart titles, subtitles, KPI labels and callout text read query results inline with `queries.<name>.one.<col>`, `.rows` and `.columns`, formatted with `| format(spec)`. [Closes dbt-labs/dbt-charts#22](https://github.com/dbt-labs/dbt-charts/issues/22)
- A query can set dialect: to the SQL dialect it was written in, and dbt Charts translates it to the source's warehouse, so one board runs on several warehouses.
- Validation errors for a key the board grammar retired now name its successor and the version that retired it, even in files that also carry new keys.
- Boards shipped in an installed dbt package's `charts/` folder show up in `dct serve`, `validate`, `render` and `impact` as `<package>/<board>`, read-only.
- A board with no width sizes to its content: tables' measured columns, titles and text. A focused chart renders at its own preferred width.
- A time axis now spans the whole date range selected with `filter_date_range()` when the chart plots the filtered column, instead of shrinking to the dates that have rows.
- A board restyles an engine format everywhere by redefining its name in `style.formats`, such as `currency` or `date_short`.
- A query's `formats:` names how each column prints, so every chart, table and KPI that shows the column uses it without repeating a format.
- Ids, durations, file sizes, coordinates, ratings and date grains each have a format name.
- Separator lines are named `divider` everywhere (was `rule`) and take `visible`, `color`, `width` and `dasharray`; boards update automatically. Table dividers take their color from the theme, so an authored table text color no longer recolors them, and a `support_table.divider` that sets `width` without `continuous` stays hidden until it also sets `visible: true`.
- A chart whose x column is a date the query turned into text (`strftime`, `to_char`, a cast to text) now warns and names the date to return instead.
- vivid-10 and editorial-10 also accept the hue names `cyan` and `moss` for the colors aliased `sky` and `sage`.
- Boards can query lake compute.
- Screen readers now announce each chart by name, with its subtitle as the description when one is authored.
- KPI content moves to the chart root and its styling under `style:` (`glyph`, `style.variant`, `style.support.format`/`tone`, `style.value.affix`/`glyph`, `style.label.overflow`), every KPI slot font now renders, and old boards migrate automatically except a theme-wide `style.charts.kpi.glyph.character`, which is removed with a warning.
- A board's `regional:` section sets its locale, for one board or a whole folder through `charts/meta.yml`: `locale.number` by name (`fr-FR` prints `1 234,5`) or as a d3 locale definition, including its thousand, million and billion abbreviations; `locale.time` for month, weekday and AM/PM names and a date picker's first weekday; and the currency symbol money formats print.
- The latest release's board JSON Schema is hosted at https://docs.dbtcharts.com/schema/board.json (each release also at /schema/<version>/board.json), and shipped boards name it in a `$schema` modeline so editors validate them.
- dbt Charts can now connect to Microsoft Fabric: install `dbt-charts[fabric]` and point a source at a Fabric warehouse through `type: dbt_profile`.
- Validate and render say each warning once per board with a count instead of repeating every instance; JSON output is unchanged.
- dct cloud can check, grant, and revoke board access, manage teams, roles, public links, and connection access, and export the audit log.
- A dbt project needs no `dbt_charts.yml`: sourceless SQL runs against the dbt profile, and a `dbt_profile` source's profile name defaults to `DBT_PROFILE`, then the project's profile. [Closes dbt-labs/dbt-charts#63](https://github.com/dbt-labs/dbt-charts/issues/63)
- A column formatted email or url links in a table cell or KPI value.
- A dbt column's meta.format prints in every board query that reads it, including after sum() and other aggregates.
- Colors and font families that cannot be valid CSS now fail at the field, and font names like Source Serif 4 are quoted.
- A `style.formats` name that nothing on the board uses now warns, with a did-you-mean when it is close to an engine format name.
- Generated tooltip, table pager and spark-bar text uses numbers and symbols instead of English words.
- search_files lists every board when the query is empty and pages long result sets with a cursor; connector results name the project and organization beside each id.
- Search results name the charts that matched on each board, and `dct describe --chart` describes a single chart. [Closes dbt-labs/dbt-charts#20](https://github.com/dbt-labs/dbt-charts/issues/20)
- Every MCP tool carries annotations (title, readOnlyHint, destructiveHint, idempotentHint) so hosts can auto-approve read-only tools, and agent sessions refuse non-GET http queries so the read-only hints hold.
- dct now sends anonymous usage statistics to dbt Labs; opt out with `DO_NOT_TRACK=1` or `--no-send-anonymous-usage-stats`.
- New `dct artifact schema` command prints the JSON Schema that board artifacts conform to; the installed package no longer includes `dbt_charts/data/schemas/board-resolved/board-resolved.schema.json`, so read the schema from this command instead.
- Warehouse queries, including BigQuery validation dry runs, record which AI tool issued them, and `dct mcp serve` reports its own surface instead of `cli`.
- Failed execute_sql results now include an error_code (an added field in --json output), and failure messages name a next step.
- The hosted connector's search and describe results list each project's queryable data sources with their SQL dialects, and a failed query names the source it ran on.
- An unformatted money or rate on a KPI or table column now warns, and the text render previews table cells through their format.
- A `cloud:` block in `dbt_charts.yml` can switch off public access and repository agent instructions in dbt Charts Cloud.
- `type: custom` draws a chart shape no built-in type has from an SVG template over the chart's query rows: `link:` makes it clickable, the template reads the board's style, fonts and variables, and ready-made Sankey, funnel, gauge, radial bar, XmR, isotype, waffle and radar templates ship as examples. [Closes dbt-labs/dbt-charts#2](https://github.com/dbt-labs/dbt-charts/issues/2)
- dct render and dct serve now keep query results in a per-user cache file by default, so re-rendering a board does not re-run its queries, and several dct processes can share one cache file.
- Postgres and BigQuery now give up connecting after 5 seconds by default.
- A board's own rows, cols, grid, tabs or tags now replace the ones it inherits from meta.yml or extends: instead of being added after them.
- `chart_rendering` and `vega:` in `dbt_charts.yml` are retired: styling values move to the theme (bar grouped padding, step-band width, support-table divider gap, KPI value compaction, stacked-area stroke width, legend row swatch and gap, footer gaps and brand weight, hover dimming), the rest become fixed engine constants. A project that sets a retired key fails with `ERR-CONFIG-KEY-MOVED` naming its new home.
- Cartesian chart errors for layered charts, step curves, overlap, and support tables now carry stable diagnostic codes.
- Board-level axis styling now follows specificity: a theme's chart-type or quantitative axis value beats the board's general one.
- Board-level settings for legend visibility and position, axis title visibility, quantitative tick count, chart title font and support table ink now take effect.
- Boards and themes can style donut charts separately through charts.donut.
- Style null is accepted only where it means no value, such as no link or a solid line; elsewhere boards are migrated and null is rejected.
- A chart, table column, or header link can open its target board in a modal with `link: {url, open: modal}`. [Closes dbt-labs/dbt-charts#5](https://github.com/dbt-labs/dbt-charts/issues/5)
- axis_y.mirror now works on a layered chart whose layers share the base's y axis.
- On a board with independent layer y axes, a layer's `axis_y.scale.domain` now clips its marks to the plot and warns when data falls outside it; `axis_y.scale.clip: false` lets them run past.
- Bar value labels take stacked: false to label plain bars while a stack shows only its total.
- marks.bar.max_size now caps the thickness of bars on a category axis.
- Table column_defaults no longer accepts label; set label on each column instead.
- Boards print generated words in their language, set by regional.language or derived from the time locale, in 19 languages.
- Style values the renderer decides accept auto, which resets a value set in a theme or parent board to the renderer's default. Legend symbol shape, point shape and title baseline accept only their named values or auto.
- The repository is now a Claude plugin marketplace: the dbt-charts plugin bundles the dbtcharts.com connector with the board authoring skills.
- Error messages name the one edit to make: the quoted YAML line, the nearest real column, the right chart key, and the strftime replacement.
- dct query SOURCE prints a data profile, and an unknown source lists the sources and data files you can use (dct query alone lists them too).
- dct serve --detach starts a background server, checks every board and prints each board's URL; dct serve --stop ends it.
- Agents read chart and styling skill pages generated from the engine, on the CLI and in the Cloud and MCP tools.
- dct describe with no board prints a project overview: sources, boards, and the tables they read.
### Fixes
- A full-width chart is no longer taller than the half-width charts beneath it: the `style.charts.max_height` default drops from 400 to 376.
- The `cloud-setup` skill connects public repositories without a browser step, checks BigQuery auth reliably, and requires warehouse grants to cover every dataset the boards read.
- A callout's tone no longer overwrites the colors its author set. `style.background`, `style.border.color`, `style.title.font.color` and `style.message.font.color`, on the chart or on the board's `style.charts.callout`, now win over the tone; the tone colors only what is still `by_tone` (the theme's default for each of those four colors). The runtime error card follows the same rule, so board-level callout colors apply to it too.
- Missing, absolute or out-of-project file references (imports, cross-file refs, `extends:`, file sources) report `ERR-UNRESOLVED-REFERENCE` naming the path instead of `ERR-INTERNAL`.
- Legends, endpoint labels and axis labels in bold or other non-default weights no longer collide with or clip their neighbors.
- Right-aligned labels on a right-hand `log` y-axis no longer cross the axis line. The label gutter is now sized for the ticks a log scale actually draws (such as "500M"). A `log` scale also now rejects, at compile time, a `domain` bound at or below 0, or a `log.base` at or below 0 or equal to 1.
- A source whose warehouse adapter is not installed now fails with `ERR-ADAPTER-NOT-INSTALLED`, naming the extra to install (`uv tool install "dbt-charts[snowflake]"` or `pip install "dbt-charts[snowflake]"`, matching how dbt Charts was installed). Before, a `type: dbt_profile` source reported an internal error (`Could not find adapter type snowflake!`), and a direct source reported a connection failure that pointed at credentials. `dct init` now prints the same hint when the detected dbt profile needs a missing adapter.
- A partial style for bar borders (`style.charts.<family>.marks.bar.border`) and pie slice labels (`style.charts.pie.marks.slice.labels`) no longer fails with field-required errors that name internal fields.
- `dct query --validate` now lints with the source's SQL dialect unless `--dialect` is given.
- A board's `html_policy` now applies to its inline nested boards, so a `- text:` row or tab under `html_policy: trusted-raw` renders raw HTML instead of escaping it. [Closes dbt-labs/dbt-charts#55](https://github.com/dbt-labs/dbt-charts/issues/55)
- A palette list entry naming a shipped palette with an unknown alias (`dbt-grays.surface`) now reports that palette's known aliases, where it reported the palette as an unassigned theme role. [Closes dbt-labs/dbt-charts#56](https://github.com/dbt-labs/dbt-charts/issues/56)
- Hovering a variable control highlights charts that read the variable through a composed query. [Closes dbt-labs/dbt-charts#54](https://github.com/dbt-labs/dbt-charts/issues/54)
- Tables warn when a column of fractions has no number format, instead of silently showing values like 437m.
- On a board with multi-column text, a block of single-column text now snaps to the card grid so its left edge lines up with the columns beside it. [Closes dbt-labs/dbt-charts#64](https://github.com/dbt-labs/dbt-charts/issues/64)
- Charts with `layers:` now use board category colors on their base `color:` field, including pinned `style.charts.category_colors`. [Closes dbt-labs/dbt-charts#57](https://github.com/dbt-labs/dbt-charts/issues/57)
- Stacked bars with `stack_order: data` on a time axis stack in query order instead of alphabetically.
- A `support_table` strip's unit suffix now hangs past the column instead of shifting its cell's digits, a warning fires when cells are wider than their category band, and `label:` on a `per_series:` entry is rejected on strip rows and stacked-bar column sets, where it was silently ignored (it still names a horizontal grouped bar's column).
- Slice and endpoint labels on a series pinned to an off-palette color take their ink from that color.
- Table columns no longer squeeze neighboring columns and wrap their headers when number values have long unformatted digits.
- `dct cloud login` sessions now renew themselves instead of expiring after 10 hours.
- A KPI `conditional_formatting` rule keyed on the `support.value` column now styles the support row (`font.color`, `glyph`, `glyph_color`, `tone`) instead of the headline; a `background` or other font key on such a rule is rejected. [Closes dbt-labs/dbt-charts#58](https://github.com/dbt-labs/dbt-charts/issues/58)
- A layered chart whose layer sets `axis_y.position: left` now rejects a chart-level y domain, as `right` already did.
- Combining `axis_y.labels.align` with a mirror whose labels can't be measured now reports a clear error that points to `axis_y.mirror.format`.
- Screen readers no longer hear NaN or duplicated values on 100% stacked, area, donut and `y_start` bar charts, and reference lines are hidden from them.
- Dashed step lines drawn with `connect: false` now end on a full dash instead of a clipped stub.
- A pie with many slices no longer raises the "too many slices" warning, and a board that still ignores it keeps loading.
- A geoshape with `value:` or `color:` but no `lookup:` now errors instead of drawing an unshaded map.
- A layer `axis_y.title` without a pinned `axis_y.position` now errors instead of being dropped.
- A `total:` on a pie with no hole now errors instead of printing over the wedges.
- `zero: false` on a bar now errors, and on an area warns, instead of silently cropping the baseline.
- A nested board's `style.layout.<type>.gap` now takes effect instead of being ignored.
- Board text no longer breaks a line between a word and the punctuation touching it.
- A board font family or color can no longer inject CSS into rendered markdown; a CSS-breaking style value now fails the board render with `ERR-STYLE-CSS-VALUE-INVALID`, not only HTML export.
- Table, pivot and KPI data mistakes (an unknown spanner or hidden column, a bad swatch color, an unparseable date, a KPI with no rows) now report a specific error code instead of a generic internal error.
- Building a warehouse connection no longer redirects other logging handlers to stderr.
- Hidden layout items no longer reserve space.
- Junk `padding`, `margin`, `border`, `gap`, `header_overflow`, `overflow` and `theme` values now raise an error instead of being silently coerced; `border` strings now accept every CSS color keyword and draw `dashed` and `dotted` lines.

- A `warnings:` block in `dbt_charts.yml` no longer stops `dct serve` from starting.
- A dark layer or board `style.background` now colors bar borders, slice strokes, and point fills with its own canvas.
- Category-count and single-point warnings now fire for colored, wide and faceted charts.
- A date pattern on an axis that holds no dates (including numbers such as epoch milliseconds) is now an error instead of painting Invalid Date.
- A bar chart with a full overlap over a color that repeats within a category now raises an error instead of drawing the series past the axis.
- Selecting a tab that is not on the board, through `--var` or a tabs `default:`, now fails with an error that lists the board's tabs instead of showing the first tab.
- A nested section with a translucent background is painted once, so it no longer renders darker than authored.
- A board's pie, donut, map and bubble map family styles (palette, background, point color) now take effect instead of being silently ignored.
- Nested boards now inherit the parent's frame, layout gaps and gap whether or not they set their own style.
- The layered-chart y-domain error now names axis_y.scale.continuous.domain, the key you actually write.
- Palette tokens in keyed style collections (such as table column colors) resolve when a board patches the style, a `theme.background` value in a table column label or style role is no longer rewritten to the canvas color, and the unknown-palette error names the resolved palette.
- The missing-currency-format warning no longer fires on columns named like index_value.
- The dual-axis competing-scales warning now points at axis_y.grid.visible: false for the interleaved gridlines.
- A bar chart on date columns named without a date-like word, such as started and finished, no longer fails as non-numeric.
- dbt stays lowercase when a subtitle in sentence case starts with it.
- Slugs and paths, such as repo names and file paths, keep their authored case under title case.
- The invalid-format error for a date format lists only the directives that slot accepts.
- The %P date directive prints am or pm on every platform.
- Integer x values from 1700 to 2100 are read as years, so historical series no longer get SI labels such as 1.6k.
- --ignore-warning accepts a retired warning code with a notice instead of failing the render.
- A board path outside the project root now reports a clear path error instead of an internal error.
- Table column_defaults set in a board or theme style now apply to the table's columns.
- A horizontal bar with multiples.columns no longer repeats its category labels at the far right of the board.
- A mirrored y-axis now prints labels on both edges when the x-axis is a number.
- A chart with a support table keeps the same title typography as its neighboring cards.
- A line of pipes that is not a table no longer hangs markdown rendering.
- Sub-day time axes tick on the clock and label whole hours, a midnight-to-midnight axis adds no date row, and tooltips show the time when data spans 48 hours or less.
- A table column with no format prints exact grouped digits when its values do not compact, instead of mixing units like 5, 1.2 K and 77.
- Serif table text renders in Source Serif instead of falling back to Times in PNG.
- marks.point.color recolors the dots of a single-series scatter chart.
- A currency axis prints a bare 0 on its zero tick, not $0.
- Boards on Redshift no longer fail to render with an undefined `postgres__list_schemas` macro.
- Editing a DuckDB or SQLite database file now re-runs its queries instead of serving stale cached results.
- Hovering a link in a table cell keeps the row highlighted and shows a pointer cursor.
- `dct validate` now accepts markdown boards, and a markdown board that cannot be parsed reports `ERR-MARKDOWN-PARSE` instead of `ERR-INTERNAL`.
- An empty pie `labels.where:` now says it must be a non-empty expression or be omitted, instead of reporting a Jinja parse error.
- Agent tools now refuse an argument they do not declare instead of silently ignoring it.
- `execute_sql` now honors `lenient_variables`, so an unbound filter variable no longer fails the query.
- A query that selects a column without grouping or aggregating it now reports ERR-BINDER-GROUP-BY with GROUP BY advice, and board-path and inline file-source mistakes carry their own error codes on every verb instead of ERR-INTERNAL.
- Replacing a detached server with dct serve --detach waits until the old server has released its port, so it no longer fails with "port in use" on Windows.
- Running several `dct mcp serve` processes at once no longer leaves one hung on its first tool call.
- A failing query now prints its diagnostic once; internal log lines print only with `dct --verbose`.
- A warehouse credentials failure is no longer cached, so dct render works right after you re-authenticate, and the error now says to refresh credentials instead of changing the SQL.
### Performance
- Charts with a title and a top support table render faster.
- dct serve shows a loading state the moment you open another board, and revisiting a board skips redrawing charts that haven't changed.
- dbt-charts no longer depends on pyarrow, so a fresh install is about 125 MB smaller; a Parquet decimal column declared wider than 38 digits now fails to load instead of narrowing.
- CSV and Parquet sources load faster.
- Listing boards by tag on Cloud no longer reads each tagged board.
- The built-in agent makes all of a request's changes to a file in one edit and sees the file's real text when an edit misses, so it finishes in fewer steps.
- Cloud chat edits boards with OpenAI's apply_patch and keeps its reasoning between steps, so review requests finish in fewer steps with fewer failed edits.
