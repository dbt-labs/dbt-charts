## 0.6.0 (2026-09-08)

A broad three-week batch: theme and grammar cleanup (several retired names and fields removed), a wave of `dct cloud` CLI onboarding fixes, and well over a hundred rendering/authoring bug fixes.

### Breaking changes

- **MetricFlow support removed:** `type: metricflow` queries, the MetricFlow-only chart `model:` sugar, and the `Variable.model`/`dimension`/`measure` fields are no longer supported — boards authoring them will need to migrate to standard SQL/dbt queries. The `dbt-charts[metricflow]` install extra is also gone, shrinking the install footprint for everyone who wasn't using it. (#7732).
- **Four inert grid keys removed: `row_height`, `default_width`, `default_height`, `gap`:** These keys were accepted by `dct validate` and documented but silently ignored by rendering. They're now removed from the board schema; use `style.layout.grid` for spacing and per-item `col_span`/`width` for sizing instead. (#7769).
- **`description:` renamed to `notes:`:** Boards, charts, queries, layout/grid/tab items, and variables now author `notes:` for non-rendering metadata instead of `description:`. This is a straight rename with no alias — the field never rendered anything (despite sitting next to `title:`/`label:`/`text:`), and boards still using `description:` need to be updated by hand; a schema auto-migration was considered but did not ship in this PR. (#7823).
- **`style.font`/`style.border` on bar, line, area, scatter, histogram, heatmap, pie, and donut now error instead of silently doing nothing:** These eight chart types never had a rendering path for chart-level `font`/`border` — the keys parsed but changed nothing, with no warning. The dead fields are removed for those chart types (with a migration for existing boards), so authoring them now surfaces a clear error instead of being silently ignored. (#7840).
- **KPI styling: `style.color` is gone, `tones` moves under `kpi`, `align` now works:** `charts.kpi.style.color` (a bare string, unlike every other chart family) is removed — use `style.font.color` or `style.value.font.color` instead. Semantic `tones` (used by both KPI and table conditional glyphs) now lives under `charts.kpi.tones` instead of being read cross-family. KPI text also gains a real `align` option instead of being hardcoded to left-aligned. Existing boards using the old `kpi.style.color` key need migration. (#7844).
- **`style.charts.table.border` no longer accepts `width`/`radius`; only markdown rule color remains:** `width` and `radius` on the table's `border` style did nothing — the table chart has no outer border to draw. Those fields are removed. The one field that actually did something, `color`, only ever painted markdown tables and `<hr>` rules on the board, not the table chart itself; it's been relocated to a board-level markdown style slot so the key name no longer misleads authors into thinking it styles their table chart. (#7858).
- **`style.columns` no longer hides unlisted table columns:** Naming a column under a table's `style.columns` used to silently drop every column not listed there. Styling and visibility are now separate: `style.columns` only styles the columns you name, and a new `visible: false` field on a column entry is the only way to hide one. Boards that relied on the old show-list behavior will start rendering previously-hidden columns until `visible: false` is added explicitly. (#7870).
- **`dct query --json` output shape changes: no `error` field, structured diagnostics:** `ExecuteQueryResult`'s duplicate `error`/`errors` fields collapse into `errors: list[str]` only, and `diagnostics` on query results is now a list of structured objects instead of raw dicts, serialized with null fields omitted. Scripts parsing the old `error` string field or dict-shaped diagnostics from `dct query`, `--validate --json`, or the MCP query tools need updating. (#7926).
- **`axis_quantitative` removed from heatmap's style surface:** Heatmap's axes are both nominal and its magnitude lives on the color channel, so `style.axis_quantitative` never had any visual effect when authored on a heatmap — it just parsed and did nothing. Authoring it now raises a parse-time error instead of silently no-op-ing. (#7952).
- **Chart attachment field renamed: `data_table:` is now `support_table:`:** The per-x-tick value strip attached to bar/line/area charts was authored as `data_table:`, colliding in name (though not in shape) with the standalone `type: table` chart. It's renamed to `support_table:` to disambiguate the two; boards using the old key need `dct migrate`. (#7984).
- **`currency` and `number` formats now default to compact, not full precision:** Authoring `number_format: currency` used to render full precision (e.g. `$400,000,000.00`); the compact form (`$400M`) required the separate `currency_compact` name. That's now flipped: bare `currency`/`number` are compact by default — matching the engine's own unauthored default — and the old `_compact` suffixes are gone. Full precision is now reached via `currency_full`/`number_full`. Any board authoring the old `currency`/`number`/`*_compact` names will render differently; update format names when upgrading. (#8102).
- **Theme set trimmed from seven to five:** Removed the unused `plain` theme and the near-duplicate `solid` theme; renamed `editorial` to `clarity` (still the shipped default) and `cream` to `paper`. `stark`, `vivid`, and `neon` are unchanged. A board authored with an old theme name (`theme:` or `extends:`) migrates to its replacement automatically. (#8326).
- **Category-axis number formats now always raise instead of silently misrendering:** A numeric `format` authored on a category axis (scatter's y as a dot plot, heatmap axes, mirrored axes) used to silently drop the format or paint "$NaN"; it's now a designed error everywhere, matching the existing `axis_x` behavior. Boards that relied on the old silent-drop or NaN rendering now need to fix or remove the format. (#8395).

### Features

- **`dct` warns when it's answering from a stale global build:** If bare `dct` resolves through `PATH` to a global `uv tool install`/`pip install` shim instead of the current checkout's own editable build, it now prints a non-fatal stderr warning naming the mismatch, instead of silently validating against an old, different source tree. (#6998).
- **Consistent category colors across a board's charts:** Charts on the same board that share a categorical column (e.g. `Electronics`, `North`/`South`) now read color from one board-wide scale instead of each chart independently sorting its own data and assigning palette slots positionally, so a value keeps the same color everywhere on the board. Adds a `category_colors` pinning option and a new `WARN-CATEGORY-COLOR-PIN-UNSEEN` warning when a pinned value never shows up in the data. (#7167).
- **`data_table` accepts bare column names:** `data_table: [resolution_rate]` now works instead of requiring `data_table: [{source: resolution_rate}]` for the common case of just listing columns. Also unblocks attaching or detaching a data table strip from Cloud's design panel, which could previously only write simple column lists. (#7661).
- **Incremental refresh for SQL chart queries:** A query or board can now declare `incremental: <watermark-column>` so warm renders refresh only the new tail of a query instead of rescanning the full history — the executor computes a watermark from cached rows and appends what's new. A nested scope can opt out with `incremental: false`; a bare `incremental: true` is rejected at parse time since there's no column to key on. (#7671).
- **New `dct examples` command:** `dct examples <name>` surfaces complete, validated board YAML from the playground gallery — multi-chart layout, query wiring, and variables working together — as a third knowledge surface alongside `dct skills` and `dct docs`. (#7680).
- **New hard limits on `files:` sources protect against runaway disk usage:** File sources (`files:` in `sources:`) had no cap on per-relation materialized size or on the number of tables in a namespace. New `execution.file_source_max_tables` (default 500) and `execution.file_source_max_bytes` (default 5GB) config keys enforce hard errors (ERR-FILE-SOURCE-TOO-MANY-TABLES, ERR-FILE-SOURCE-TOO-LARGE) before a large or wide file source is read. (#7794).
- **Bar and histogram marks gain a `fill_opacity` field:** `style.marks.bar.fill_opacity` is now accepted (histogram charts share bar marks, so they get it too), matching the opacity field already available on area, point, rule, rect, and circle marks. Useful for keeping bin/bar boundaries visible when bars sit close together. (#7833).
- **KPI cards can now center- or right-align their text:** KPI values were hardcoded to left-aligned text. A new `align` field on KPI styling accepts `left | center | right`, matching the alignment already available on table columns. (#7873).
- **`dct validate --warehouse` now checks Postgres, Redshift, and Snowflake:** Warehouse-level query validation previously worked only for DuckDB and BigQuery; every other adapter reported `unchecked`. Postgres, Redshift, and Snowflake now get real validity checks via `EXPLAIN`. Also adds `dct init ci`, which scaffolds a GitHub Actions workflow that runs `dct validate charts` on pull requests. (#7879).
- **New `dct impact` command finds boards affected by a column change:** `dct impact COLUMN [--table] [--json]` answers "which boards break if this column changes" by building a reverse index from warehouse columns to the boards and queries that reference them, using compiled board SQL and no warehouse connection. Unparseable SQL, `SELECT *`, and boards that fail to compile are reported as indeterminate rather than silently omitted. (#7893).
- **`dct validate` catches renamed dbt columns before you run dbt:** A new check derives each dbt model's output columns statically from the compiled SQL in `target/manifest.json` (a bare `dbt parse`, no build or warehouse credentials needed) and checks board queries against them. Renaming a column in a dbt model now fails `dct validate` immediately, instead of passing with a false green until `dbt run` rebuilds the warehouse and `--warehouse` validation finally catches it. (#7935).
- **`dct validate` catches table-column errors without a full render:** `ERR-TABLE-COLUMNS-TRANSITION` used to fire only when a board rendered, so there was no way to sweep a repo of boards for it ahead of time. `dct validate` (including `--warehouse`) now surfaces it directly. A related bug where a zero-row query result silently passed the check unnoticed is also fixed. (#7979).
- **Line charts show data points automatically at low density:** A line chart now draws a point marker at each observation once points are sparse enough (roughly 18px apart on the rendered card), sized relative to the line's stroke with a knockout halo, so individual observations are visible without hand-tuning mark sizes. (#7986).
- **New `dct cloud` command surface:** Adds `dct cloud` commands to drive dbtcharts.com Cloud setup from the terminal: `use`, `status`, `orgs`/`org create`, `projects`/`project connect` (GitHub picker handoff or headless `--git-url`), `project sync`, `connections`/`connection create`/`connection test`, `sources`/`source map`, and `render`. Every verb supports `--json` output for scripting. Auth token is stored in a new 0600 user config file, overridable with `DCT_CLOUD_TOKEN`. (#8143).
- **`dct cloud` gains org management verbs:** New verbs manage members, invitations, connections, projects, and grants directly from the CLI: invite or remove members, revoke or resend invitations, delete or refresh connections, delete projects and orgs, and list or revoke grants. Destructive verbs confirm with the full `org/slug` coordinate, even under `--yes`. (#8147).
- **New `cloud-setup` skill teaches the CLI the full Cloud onboarding journey:** `dct init skills` now installs a `cloud-setup` skill that walks an agent through org, project, and connection setup end to end: least-privilege credential minting per warehouse, when to use `--git-url` versus the GitHub App hop, and the `dct cloud status` polling loop. (#8149).
- **`dct cloud login`, `logout`, and `whoami`:** New CLI commands authenticate against dbtcharts.com via OAuth device-code flow: `dct cloud login` opens a browser for org consent, `dct cloud whoami` shows the signed-in identity, and `dct cloud logout` clears the stored session. (#8259).
- **`support_table` now works on horizontal bar charts:** The attached value-column strip was previously limited to a horizontal band above/below charts whose category axis is x. It now also renders as vertical columns beside the plot when the category axis is y — e.g. a horizontal bar ranking with a numeric column next to each bar. (#8342).
- **`y: [a, b]` with `color:` now works for composite measure-by-dimension series:** Authoring multiple `y` measures together with a `color:` dimension used to raise `ERR-MULTI-Y-COLOR-CONFLICT`. It's now allowed on bar, line, and area charts, rendering one series per measure-by-dimension combination -- the shape produced by MetricFlow and other pivoted semantic-layer results. (#8414).
- **`dct init` now scaffolds a `sources:` example:** The `dbt_charts.yml` template written by `dct init` now includes an example `sources:` block, and `dct docs` gained a topic covering project source registration — previously neither surfaced any DuckDB/file-source example, leaving new projects to guess the syntax. (#8544).
- **Clicking an auto-linked chart now shows a loading spinner:** Clicking a bar or point with an auto-generated drill-down link previously gave no feedback while the destination board loaded, which could take seconds — users would click again or assume the page was stuck. The clicked chart now dims and shows a spinner while the browser navigates, in both `dct serve` and Cloud. (#8551).
- **Board footer now shows the dbt charts mark, not just text:** Every rendered board's footer draws the full dbt charts wordmark (mark + "dbt" + "charts") in place of the old plain-text phrase, filled with the footer's own muted font color instead of brand orange, so it reads as a quiet watermark on any theme. The wordmark carries the footer link by default; set `link: null` to make it non-clickable. (#8581).
- **`dct query` can now read CSV/JSON/Parquet file sources:** `dct query`, `dct query board.yml <chart>`, and the `execute_query`/`query_board` MCP tools used to refuse any file-backed source ('File sources are read by the render path only'). They now share the same file-source reader as `dct render`/`dct serve`, so you can explore a file-source project's data ad hoc before writing a chart. (#8616).
- **`dct docs --search` ranks results instead of requiring an exact substring match:** Multi-word queries used to require an exact substring inside one of 10 fixed doc sections, and failed about 70% of the time in practice. Search now ranks over the full doc corpus — including the generated field, error, and warning references — with BM25, and `--search` can now be combined with `--topic` to scope results instead of erroring as mutually exclusive. (#8633).
- **`dct cloud render` gets a `--force` flag; mapping a source now invalidates stale renders:** A warehouse project's first render fires on sync, before any connection is mapped, so every card used to come back `ERR-SOURCE-NOT-FOUND` and stay that way permanently — mapping the connection afterward invalidated nothing and there was no way to force a re-render. Source mappings are now part of the render freshness key, so mapping, re-mapping, or unmapping a source triggers a re-render, and `dct cloud render --force` re-renders regardless of freshness. (#8637).
- **`dct cloud boards` now shows when a board last rendered and from which commit:** New RENDERED_AT and COMMIT columns let you confirm your latest push is actually live, instead of guessing from a `ready` status that looks identical before and after a render. (#8656).
- **`dbt_charts.yml` can now record where a project is published:** A new `published_to:` key, written automatically by `dct cloud project connect`, records the Cloud org/project URL in your project config. `dct cloud` commands and `whoami` read it directly instead of inferring the target from your git remote. (#8658).
- **`dct cloud login` gets non-blocking `--start`/`--wait` modes:** `dct cloud login` used to block in the foreground for up to 30 minutes with no alternative, forcing scripts and agents to background it and scrape a shared, world-readable log file. You can now start the login separately, capture the approval URL immediately, and wait for completion on your own schedule, without racing another concurrent login. (#8662).
- **New `dct skills intro` orients any coding agent from a single sentence:** A CLI-only `intro` skill gives an agent that has never used dbt charts everything it needs on one page: what the tool is, where data can live, the validate/render/serve loop, and links to every other CLI workflow skill. (#8672).
- **`dct init skills --global` installs workflow skills once per machine:** Installs the CLI-rendered workflow skills into `~/.claude/skills` or `~/.agents/skills` once, so a brand-new, unrelated project folder can still trigger the `intro` skill without running `dct init skills` in that repo first. (#8674).
- **New warning for overlapping axis labels:** Line/area/scatter charts now emit `WARN-AXIS-LABEL-COLLISION` when x-axis tick labels still overlap after every overlap-avoidance strategy (skip, tilt) has been tried, instead of silently rendering overprinted text. The warning points authors at the fix: widen the chart, coarsen the grain, filter the data, or shorten labels. (#8718).

### Fixes

- **`dct migrate` no longer breaks on boards using newer keys:** Adding a key introduced after the last frozen schema (`theme:`, `html_policy:`, `style.frame:`, `nice:`, `collapse:`, `max_number:`, etc.) to an old-shaped board used to silently disable migration for the whole file, producing validation errors that named retired syntax the author never touched. Migration now checks for retired constructs individually instead of requiring a whole-document match, so newer keys no longer strand old boards. (#7608).
- **Long axis titles no longer collapse scatter and heatmap charts:** Scatter and heatmap axis titles now pre-wrap to at most two lines against the axis title budget, matching bar/line/area. Previously an unwrapped long `x_label`/`y_label` on these two chart types could reserve so much space that the plot area shrank to a sliver. (#7621).
- **Case-transformed titles no longer overlap chart content:** Title height was measured from the authored text but drawn after applying the case transform (`case: title` is the base theme default), so title-cased text could be wider than the space reserved for it and spill into the chart below. Measurement now uses the exact string and width that get drawn. (#7630).
- **`dct search` no longer misses prose-only or extends-only boards:** Boards built purely from `extends:` or free-form `text:` content were invisible to `dct search` and the board index because the CLI's key list didn't agree with the file's own schema. Both now derive from the same schema facets, so any board that renders is also indexable. (#7657).
- **`link: false` now actually suppresses a chart's auto-link:** With `auto_link: true` on a board, there was no working way to opt one chart out despite the docs claiming `link: ~` or `link: none` would do it — neither worked (a silent no-op, or a literal `href="none"`). `link: false` is now a real, typed suppression that survives `extends`/patch merges. (#7659).
- **dbt manifest version mismatches no longer hard-fail ref validation:** `ERR-DBT-MANIFEST-INCOMPATIBLE` fired whenever `target/manifest.json`'s schema version fell outside the installed dbt-core's supported range, even though the loader reads the manifest fine regardless and never deserializes through that typed contract. The gate is removed, so an incompatible-looking manifest no longer blocks a render. (#7660).
- **Pie charts no longer flake with `ERR-RESOLVED-PIE-DATA-MISMATCH` on tied sort order:** A pie chart whose query has an `ORDER BY` with tied values (e.g. two categories both counting 2) could intermittently fail to render, because resolve and render re-executed the query separately and could get different row orders back from the warehouse. Execution is now shared and memoized across resolve, render, and record, even with `--no-cache`. (#7668).
- **`time_format: currency` now rejected at parse time:** Time-format fields no longer accept number-format aliases like `currency`, `percent`, or `integer` — these used to compile clean and render garbage tick labels on a temporal axis. `time_format` now only accepts time-flavored aliases (e.g. `date_short`) or a literal d3 time spec (`%b %Y`); anything else raises a compile error instead of a broken chart. (#7669).
- **Y-scale mismatch warning now catches layered charts with per-layer queries:** The layered-chart shared-y-axis scale-mismatch warning used to skip any chart where a layer carried its own `query:` — exactly the shape produced by migrated multi-metric dashboards. It now fires there too, naming both columns and prescribing `axis_y:` instead of silently rendering one series as a crushed flat line. (#7672).
- **Line and area charts with no `y:` no longer crash:** Two legal-but-crashing board shapes now render instead of raising `ERR-INTERNAL`: small multiples (`multiples: {columns: ...}`) or an authored `style.axis_y.mirror: true` on a chart with no `y:`, and a line or area chart authored with neither `x:` nor `y:`. (#7673).
- **`dct render`/`dct serve` no longer fail on DuckDB warehouse conflicts:** Rendering a DuckDB-backed board could fail with "Can't open a connection to same database file with a different configuration than existing connections", even though nothing about the connection had changed. Fixed by no longer letting dbt-duckdb's `keep_open` pin the warehouse to a stale configuration. (#7701).
- **Pivot table columns now sort chronologically or numerically instead of by first-seen order:** Pivoted columns (e.g. a month pivot) used to appear in whatever order the query happened to return them, which could render a chronological series out of order. Columns are now sorted chronologically when they hold calendar values, ascending when numeric, and left in query order otherwise. (#7703).
- **Value labels no longer draw phantom axes on dual-axis charts:** Turning on value labels on a dual-axis/layered chart used to draw extra, unauthored y-axes titled with raw internal field names. Value-label sublayers no longer generate their own axis. (#7704).
- **Board text baselines now match real font metrics:** Headings and body text were positioned assuming a font's ascent is exactly one em, which is never true for real typefaces, so every heading sat slightly low (worse at larger sizes). Baselines are now computed from the font's actual ascent/descent, so titles and headings land where authored. (#7707).
- **Tables and grids no longer silently under-render rows:** The table sizer (which reserves layout space) and the paginator (which decides how many rows to draw) could disagree, so a table could reserve space for 6 rows but draw only 3, with `dct validate` and `dct render` both exiting clean and no warning shown. The two are now reconciled, and a mismatch surfaces a warning instead of silently truncating data. (#7711).
- **Styling a pivot table's row/group column no longer collapses the cross-tab:** Adding a `style.columns` entry for a pivot's row/group field (e.g. relabeling `region`) used to silently drop every value and quarter column, leaving just the one relabeled column with no warning. The fix keeps the full cross-tab intact. (#7712).
- **Bar value labels no longer scramble the x-axis on layered charts:** Turning on `marks.bar.labels.visible` on a chart with two complementary bar layers (e.g. actual vs. forecast) could reorder the x-axis into layer-paint order instead of chronological order, silently misrepresenting the trend. The x-axis domain is now independent of label rendering. (#7713).
- **KPI `style.value.font.color` and `style.label.font.color` now work:** Both keys validated and rendered without error but were silently ignored: KPIs kept the theme's default color, and only `style.color` actually applied, even overriding the more specific key when both were set. Both keys now take effect as authored. (#7714).
- **`conditional_formatting` no longer overwrites an authored label color:** Adding a `conditional_formatting` block to a bar chart used to repaint every value label with the bar's own fill color, discarding an authored `style.marks.bar.labels.font.color` and sometimes making a label unreadable against a same-colored bar. The authored color is now preserved. (#7715).
- **Legend visibility and position keys now behave as authored:** Fixed three legend bugs that all shared one root cause (endpoint-label suppression overriding the legend): `legend.visible: true` was silently discarded whenever endpoint labels were on, `legend.position: bottom` rendered no legend at all, and `legend.position: none` overlaid the legend on top of the plot instead of hiding it. All three now do what the key name says. (#7716).
- **Variable control text no longer overlaps its chevron or calendar icon:** Select, multiselect, and date filter controls previously drew their value text hard against the ornament glyph (e.g. "All⌄" with the chevron overlapping the last letters). A consistent gap is now reserved between value text and ornament at every viewport and value length, and an unset date field no longer collapses to a bare glyph with no field affordance. (#7717).
- **Format and sizing fixes: `$~s` precision, text grid height, table date format:** `format: "$~s"` no longer renders full precision (e.g. `$50.7529k`) when it should render a short, trimmed number. A text item in a `grid:` layout no longer reserves a full chart's worth of vertical space for a one-line heading. Table date columns gain a date-format option instead of always falling back to raw values. (#7718).
- **Prose text now starts level with an adjacent chart's title:** A text column's opening heading previously sat noticeably lower than a sibling chart's title in the same row, because the heading's top margin and the prose band's vertical inset were handled inconsistently. Prose now aligns with chart content at the top of a row the way it already did horizontally. (#7754).
- **Clearing a date-range filter no longer breaks the board:** An empty `daterange` variable value (e.g. after clicking "clear" on a date picker) previously raised an error and failed every chart on the board. It now resolves to unset, like every other typed variable, and charts render unfiltered instead of erroring. (#7777).
- **Chart label text no longer depends on the machine's local timezone:** Charts whose axis labels come from a local-time Vega expression used to render different text depending on the host machine's timezone (e.g. "Apr 2024" vs "Mar 2024" for the same data and query). Render timezone is now pinned so output is deterministic regardless of where `dct` runs. (#7782).
- **Docs no longer claim `cols: [chart, 2]` sets a column span:** `DBT_CHARTS_SYNTAX.md` and the packaged agent skills (served by `dct docs` / `dct skills`) claimed a trailing integer in `cols:` sets a fractional column span; that doesn't compile. The example is fixed to point authors at `grid:` for column spans, and every fenced example in shipped docs/skills is now compile-checked. (#7787).
- **Board migrations no longer corrupt variable defaults that happen to look like charts:** A migration rewrite rule matched any object with a `type:` key equal to a chart family, even outside chart positions, so a `Variable.default:` value shaped like a chart could get silently rewritten and lose data during automatic migration. Migration appliers now only fire on actual chart positions. (#7789).
- **Line, area and scatter no longer drop axis labels under an overlay:** When an overlay layer covered more x buckets than the base series, only the base's share of the x-axis got labels — the rest of the domain rendered bare with no warning. Fixed for line, area, and scatter (bar was already fixed by a prior release). (#7805).
- **Series-label rail no longer stacks overflow labels on top of each other:** Past the point where the endpoint-label rail ran out of vertical space, every remaining label was emitted at the same y position, painting an unreadable smear. The rail now surfaces a warning when it can't fit every label instead of silently overlapping them. (#7809).
- **`board.width` now warns when content is too narrow to reach it:** Authoring `width: 1800` on a board didn't guarantee 1800px — the container is capped at `min(board width, measured content width)`, so a board of default-sized charts could silently render hundreds of pixels narrower than authored, with colliding axis labels and no warning. A cramped-table warning now surfaces when the authored width can't be honored. (#7810).
- **Temporal x-axis labels can now reach yearly cadence:** The label cadence ladder took only one step up from the data's native grain, so `year`-level labels were unreachable from monthly, weekly, or daily data at any chart width — a long monthly series would fall back to tilted quarterly labels instead. The ladder now climbs multiple rungs to find a cadence that fits. (#7812).
- **Faceted small multiples no longer reserve space for series absent from that panel:** Splitting a chart into small multiples by a field (`multiples: {rows: series}`) faceted the data correctly but built each panel's inner encoding (bar color domain, heatmap y-axis) from the whole field's domain — so a panel with one series still reserved space and axis rows for all of them, painting narrow bars and phantom empty rows. Each panel's inner domain is now restricted to the values it actually contains. (#7814).
- **KPI `inline` variant no longer overprints the next card:** With `variant: inline` and all three of label, value, and support authored in a narrow KPI card, the support text used to overflow the card and print over the neighboring chart. It now falls back to a layout that fits, with a new warning when the fallback kicks in. (#7832).
- **`spark_bar` numeric validation no longer depends on `max_bars`:** spark_bar used to validate only the rows visible under `style.spark_bar.max_bars`, so the same data and query could pass or fail `ERR-SPARK-BAR-VALUE-NOT-NUMERIC` depending purely on that display cap. The check now covers the full dataset, so changing `max_bars` can no longer flip a board between erroring and rendering. (#7834).
- **Merged legends no longer draw overlay entries larger than base series:** In a legend merging a color-encoded base series with an overlay layer, the overlay's entry used to render at double the length and a heavier stroke than the base entries beside it, making it look artificially emphasized. Same-shape entries now render at a consistent size. (#7835).
- **Faceted chart legends no longer spill past the card edge:** A `multiples:` chart with a color legend (or a heatmap's continuous value-scale legend) now reserves space for it when sizing facet panels, instead of painting the legend at its natural width past the card's declared boundary. (#7836).
- **Grouped bar charts with layers no longer render invisible bars on a quantitative x-axis:** A color-grouped bar chart (`color:` + `stack: none`) with authored `layers:` on a continuous/quantitative x-axis rendered zero-width, invisible bars. Bars now size correctly, and a new warning flags grouped series that would otherwise render coincident. (#7838).
- **Axis titles now visible by default, and keep your column casing:** Cartesian charts previously emitted axis titles with a font size of 0, so they never showed even though the engine derived them from the bound column. Default axis titles now render, and they preserve the query column's original casing (`total_revenue`) instead of Title Case (`Total Revenue`). Explicit `x_label`/`y_label`, chart titles, and legend titles are unaffected. (#7842).

- **`dct cloud project connect` no longer blocks or leaks its install URL to a shared log:** Split into `--start` (prints the install/pick URL, returns immediately) and `--wait` (blocks until the pick completes), mirroring the fix already shipped for `dct cloud login`. Closes a real leak: two concurrent `connect` runs previously shared one world-readable `/tmp` log file, and could hand a user the wrong organization's install URL. (#8693).
- **Fixes false-positive `WARN-REAGGREGATION`/`WARN-FANOUT-RISK` and a silently-inert `warnings_ignore`:** Both warnings previously matched on column alias name rather than actual lineage, so an unrelated CTE reusing the same alias, or a purely cosmetic table-qualification change, could flip a warning on or off with no real change. `warnings_ignore` was also chart-scoped and validated cleanly against these query-level warnings while silently doing nothing to suppress them; it now actually works. (#8695).
- **`dct cloud login`/`project connect --start` now hints the required `--wait` follow-up:** An agent that ran `--start` and never followed up with `--wait` could leave a connect/login half-finished with no signal. `--start` now prints a `Next: ... --wait` hint on stderr, and the CLI skill runs `--wait` immediately after `--start` in the same turn. (#8698).
