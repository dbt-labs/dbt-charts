## 0.7.0 (2026-09-11)

A correctness pass across chart rendering, sorting, and style cascading, plus a `dct serve` security fix, three breaking grammar cleanups, and an 11x faster board parser.

### Breaking changes

- **`style.color` and `style.page.background` removed from the board grammar:** `style.color` never affected rendering, and `style.page.background` only ever painted the exported HTML page background, which is now hardcoded white. Boards authoring `style.page` migrate automatically; boards authoring `style.color` fail to compile since there is no safe automatic replacement (#8491).
- **Shipped skills install under a `dct-` prefix and overwrite unconditionally on upgrade:** `dct init skills` now writes skills into namespaced `dct-*` directories so they never collide with a project's own skills, and re-running it after an upgrade always refreshes skill bodies instead of silently skipping existing files. The `-f`/force flag and the old un-prefixed skill directories are gone; skills retired from a release are now swept automatically (#8850).
- **`conditional_formatting` removed from bar, line, area, scatter, pie, map, and other non-table/KPI charts:** the key only ever honored `rule.background` on these chart types and silently dropped `font`, `glyph`, `glyph_color`, and `tone`; it's now removed there entirely, with an automatic migration deleting the key from those boards. `table` and `kpi`, where it fully works, are unaffected (#8490).
- **Pie/donut chart total format moves from `total.format` to `style.total.value.format`:** a format string is paint, not authored copy, so it now lives under `style.total.value.format` alongside every other format field (tooltip, bar total label, axis labels); existing boards using the old `total.format` key keep working, auto-migrated in place. Authoring `style.total.label` as a caption now gets a clear error pointing back to `total.label:` instead of a raw extra-field error (#8828).

### Features

- **Hover emphasis now covers lines, areas, scatter, pie/donut, and heatmaps:** hovering a chart now visually ties the tooltip to the data it describes on every chart family: bars, histograms, pie/donut slices, and categorical heatmap cells recede toward the background, while lines, areas, and scatter get a marker dot (or ring) and a neutral drop line to the baseline. Charts whose color encodes a value never recede, since dimming would misrepresent the magnitude; turn the whole feature off with `style.charts.hover_emphasis.visible: false` (#8827).
- **Board renders now cap total template output; oversized boards fail fast instead of exhausting memory:** a board render's cumulative Jinja-emitted output is now bounded by a configurable byte ceiling (`execution.max_template_output_bytes`, default 50MB), raising a new `ERR-TEMPLATE-OUTPUT-TOO-LARGE` error instead of letting a small amplifying template, such as nested loops, emit an unbounded amount of text (#8735).
- **Zero/threshold baseline now renders on scatter charts and every quantitative axis:** the bold rule marking zero (or 100% on a percent axis) now fires on any quantitative axis, not just bar/line/area's measure axis, so a scatter plot crossing zero gets a baseline too. The authoring key `grid.zero` is renamed `grid.threshold` and gains a `visible` switch to turn off just that rule without hiding the whole axis's gridlines (#8343).
- **Single-series area charts now render with a solid fill instead of a washed-out translucent one:** the translucent overlap fill, meant to signal overlapping series, was applied even when there was nothing to overlap. A single-series area chart now gets the same solid fill and edge treatment as one authored with `style.stack: zero` (#8729).
- **`dct init` starter board now uses real SQL and a working filter:** the scaffolded `guide.yml` board now queries a sample CSV with real SQL and a filter control that actually re-runs the charts, replacing an inert filter and a detour into unsupported markdown boards. New users see a board that behaves correctly from the first render (#8794).
- **`dct init` starter board no longer ships a sample CSV file:** the starter board's sample data now lives inline in the YAML as `values` queries instead of a scaffolded CSV, so `dct init` no longer drops a data file into new projects. The region control now drives the board's own explanatory text, since inline rows can't be filtered by a variable (#8808).
- **Board footers show "made with dbt Charts" as text, not a logo:** the SVG wordmark lockup in every board's footer is replaced with live text, "made with dbt Charts", set a weight heavier than the surrounding words and still linked to dbtcharts.com. The change also fixes an emphasis bug in the previous text-based footer: PNG and PDF exports could not resolve the CSS rule that bolded the name (#8755).

### Fixes

- **`dct serve`'s directory listing no longer lets a crafted filename inject template code:** a file whose name contained Jinja syntax could have that name evaluated as template source on the next render pass. Filenames are now passed through as plain variable values, so a filename can never be re-tokenized as code (#8730).
- **Broken chart queries no longer get silently reported as successful:** a query failure that wasn't a plain execution error, for example a Jinja template error in SQL or a too-large-template-output error, could lose its error code and be swallowed into an empty chart instead of a recorded failure, making board-artifact generation report success on a board with a genuinely broken chart; this path now surfaces the failure correctly (#8743).
- **Charts no longer silently drop every row when dates fall on period ends:** a time series reported at month-end, quarter-end, or similar period-end dates (for example `LAST_DAY(month)`) with an authored `time_unit` used to render a full axis with zero data points and no warning; rows are now matched to the bucket they fall inside, and two rows landing in the same bucket now raise a clear `ERR-GAP-FILL-BUCKET-COLLISION` error instead of one silently overwriting the other (#8739).
- **`sort:` is respected on layered charts that also use `color:`:** a bar chart authoring `color:`, `layers:`, and `sort:` together silently rendered its x-axis alphabetically, discarding the sort key, direction, and query row order, so a time series could read as scrambled with no warning. Layered categorical x-axes now keep the intended order. One side effect: a layered scatter chart, which has no sort key of its own, now renders in query row order instead of alphabetical (#8785).
- **`sort:` now works on area, line, and heatmap charts:** `sort:` was previously silently ignored on area, line, and heatmap charts (only bar and scatter honored it), so a warehouse query returning rows in a different order could reverse a chart's axis with no warning. All five documented chart types now honor `sort:` (#8796).
- **Chart x-axis labels no longer misread month-end, quarter-end, and year-end data as daily:** time-axis grain detection now looks at the spacing between dates instead of where they fall on the calendar, so month-end, quarter-end, year-end, and fixed-day-of-month series get the correct monthly/quarterly/yearly tick ladder instead of one gridline and label per day (#8815).
- **Line, area, and scatter charts no longer draw hundreds of extra gridlines on sparse date data:** sparse monthly or quarterly data on a line, area, or scatter chart could be misdetected as daily grain, drawing over 1,000 gridlines that rendered as a solid gray band; these chart types now use the same grain-budget check bar charts already had (#8737).
- **`style.legend.values` now actually reorders and filters legend entries on every chart type:** the authored legend order was previously overwritten on most chart families, and matching an entry meant guessing a per-family label spelling. Entries now resolve by rendered label or by column/measure name, and an entry that still can't be matched produces a warning instead of silently vanishing from the legend (#8430).
- **Old boards using dead style keys (`style.color`, `kpi.style.color`, and others) no longer fail to load:** four keys retired in earlier grammar versions (board-root `style.color`, `kpi.style.color`, `style.charts.kpi.color`, and heatmap's chart-local `style.axis_quantitative`) are now migrated away automatically instead of raising an `extra_forbidden` error, so old boards that still authored one of them load again (#8848).
- **`dct render` now resolves `env_var()` templating in `profiles.yml`:** profiles fields that dbt renders via Jinja, such as a Snowflake `private_key_path` built from `env_var(...)`, no longer reach the file system as a literal template string. Any dbt project relying on templated `profiles.yml` values can now run `dct render` (#8854).
- **`dct query --validate` and `--describe` no longer fail on boards using `ref()`:** both flags previously errored with a raw "Jinja template error: Undefined variable: 'ref' is undefined" on any board query using `ref()`, even though `dct query`, `dct render`, and `dct validate` ran fine on the same query. They now resolve refs the same way execution does, and a project with no dbt manifest gets a clear `ERR-DBT-MANIFEST-MISSING` instead of the Jinja error (#8776).
- **Cloud connection tests no longer hang for minutes on an unreachable warehouse:** testing a connection to an unreachable warehouse (firewalled, wrong host, black-holed DNS) could previously block a worker for up to 5 minutes; connection tests, including `dct cloud connection test`, now time out within about 15 seconds and still surface the driver's real error message when one is available (#8805).
- **`dct cloud connection create` for BigQuery no longer hangs indefinitely, and its failure message stops contradicting itself:** BigQuery dataset discovery, location lookup, and per-relation readability probes are now time-bounded like the connection test, so a slow or unreachable warehouse fails fast instead of parking the request for minutes; the CLI's connection-create failure message no longer mixes reachability advice and credential advice for the same error (#8821).
- **Nested board items no longer lose ancestor style overrides once they author their own style block:** a board-root override such as `style.font.color` used to stop reaching a nested title/text item the moment that item authored any `style:` block of its own, even something unrelated like `padding`. Ancestor-authored values now cascade to every descendant regardless of which field the descendant styles itself (#8715).
- **`style.layout.rows/cols/grid.gap` no longer leaks into nested boards with their own style:** a board's own `rows.gap`, `cols.gap`, or `grid.gap` setting stopped overriding a nested board's spacing when that nested board authors its own style block, matching the same fix already shipped for `style.gap`, `margin`, `padding`, `frame`, and `color` (#8736).
- **Number-format aliases defined on a board no longer disappear inside tabs that set their own style:** a `style.formats` alias table defined on a board, and the design panel's list of usable aliases, stopped being visible inside a tab item that authored any style of its own, such as a background color; format aliases now correctly cascade into styled nested scopes (#8741).
- **Tab items with only text, or no content, now keep their own style block:** a tab item authoring just text and a style override, or nothing at all, previously discarded its own style and silently rendered with the parent board's style instead; it now applies correctly (#8744).
- **Board fonts and colors no longer bleed between boards embedded on the same HTML page:** multiple boards on one page shared a single global CSS scope, so the last board's fonts and text colors silently overrode every earlier board's (visible on the docs theme gallery, and anywhere two themed boards share a page). Each board's styles are now scoped so themes stay independent when embedded together (#8725).
- **Boards composed on the same page no longer bleed into each other's gradients and clip paths:** combining multiple rendered boards in one HTML document could make a second board's gradient or clip-path reference resolve to the first board's definition, because vl-convert's id counters reset per render call and collided across processes. Referenced ids now carry a content-derived token so two boards never collide (#8752).
- **Chart tooltips, bullet legends, and donut breakdowns render correctly again:** fixes four rendering bugs: tooltip color swatches were invisible (painted white-on-white) on multi-series line and bump charts, a bump chart's tooltip printed a raw epoch integer instead of the year, a two-row donut breakdown incorrectly inherited the data table's zebra striping, and the bullet chart's legend order and gray ramp didn't match its bands' meaning (#8811).
- **Scatter tooltips no longer print raw epoch numbers for date-like x values:** hovering a scatter point whose x axis is a labeled date bucket (e.g. "Q1 2024") previously showed a raw epoch-millisecond integer or an oddly formatted year in the tooltip; the tooltip now matches what the axis shows (#8814).
- **Overlay chart tooltips no longer collapse multiple colored series into one row:** a cartesian chart layer using `color:` to draw multiple series (for example, a colored line overlay) showed every series correctly on the chart and in the legend, but the hover tooltip merged them into a single mislabeled row. Each series now gets its own tooltip row (#8862).
- **Horizontal bar charts repeat currency prefixes on every axis tick:** a horizontal bar chart with a plain currency format (e.g. `$`) on its measure axis previously showed the symbol on only one tick, making the rest look like unitless numbers. Every non-zero tick now carries the prefix, matching the compacting (K/M/B) currency format's existing behavior (#8803).
- **Axis titles ellipsize instead of splitting a word across two lines:** a y-axis title like "commits" could render as "commit" / "s" on facet panels with no warning, because the wrap logic broke mid-word rather than ellipsizing. Titles that don't fit are now ellipsized and raise `WARN-AXIS-TITLE-TRUNCATED` when appropriate, and facet panels get an axis-title budget sized to the panel instead of the whole chart (#8784).
- **KPI and table card backgrounds now fill the whole card, matching charts:** a `style.background` color on a KPI or table card used to stop short at the card padding, leaving a smaller tinted rectangle inset from the edge; it now fills the same full-bleed area a chart's background does (#8825).
- **Line charts no longer announce every value twice to screen readers:** the invisible hover-target overlay on line charts now drops its own accessibility label whenever a visible point mark exists for the same datum, cutting doubled announcements (for example, 48 down to 24 labels on a 12-month line) without changing hover or tooltip behavior (#8820).
- **Currency/percent formatter warning now catches bare field names like `share` or `mrr`:** `WARN-LIKELY-CURRENCY-OR-PERCENT-MISSING-FORMATTER` previously only matched suffixed field names (`_share`, `_rate`); it now also flags common bare names such as `usd`, `revenue`, `mrr`, `share`, and `pct`, catching more boards that would otherwise render a fraction as "350m" or drop a currency symbol (#8860).
- **Validation errors inside nested `tabs:`, `grid:`, or `foreach:` now point to the right location:** a bad reference inside a nested board's tabs, grid, or foreach block used to fall through to a generic, positionless error. The validator now walks the full layout tree, so these errors report the same file position and range as top-level ones (#8855).
- **`dct init skills --project-dir` now installs into the directory you name:** the flag previously installed skills into the enclosing git root instead of the given `--project-dir` path, with no warning. It now installs into the named directory, and pointing it at a directory with no dbt project or dbt Charts config raises a clear error instead of silently resolving upward (#8861).
- **`dct init` scaffolds `.yml` consistently and adds a README:** the starter project's guide and meta files are now `guide.yml` and `meta.yml` instead of a mix of `.yaml` and `.yml`, matching every other board in the product, and `dct init` now writes a `README.md`. Both suffixes are still accepted when reading boards (#8792).
- **IDE extension diagnostics work out of the box, no manual pygls/lsprotocol install needed:** the dbt Charts VS Code extension now vendors its own LSP protocol dependencies, so installing the extension alone is enough to get board diagnostics; previously the language server crashed silently unless the user separately had pygls and lsprotocol importable on their Python interpreter. A missing dbt-charts install now reports as a clear diagnostic naming the resolved interpreter and install command instead of a silent crash loop (#8731).
- **Default board title and aria-label now read "dbt Charts", not "dbt charts":** the default board title (the accessible name screen readers announce), the `dct init ci` workflow name, and the scaffolded starter board previously forced the lowercase spelling regardless of what was authored; corrected across 80 rendered boards with no layout change (#8724).

### Error messages

- **PDF and PNG export failures now show an actionable error instead of `ERR-INTERNAL`:** a failed PDF or PNG export (for example, an SVG too deeply nested to convert) used to surface as a generic `ERR-INTERNAL` with a raw third-party message and no help link. It now raises a registered `ERR-FORMAT-CONVERSION-FAILED` or `ERR-FORMAT-CONVERTER-UNAVAILABLE` error that suggests an alternative export format (PNG or HTML) (#8858).
- **`WARN-TOO-MANY-X-CATEGORIES` gives an accurate message on temporal bar charts:** a monthly time-series bar chart with 76 buckets triggered a warning claiming label collisions and citing a limit of 50 (both wrong for that chart), plus fix suggestions (top-N filtering, coarser grouping, a table) that don't apply to a time series. Temporal bar axes now get their own accurate wording and fix text; the categorical case is unchanged (#8777).
- **`style.axis_x.title` errors now point to `x_label`/`y_label`:** authoring `style.axis_x.title` (or `axis_y`, etc.) as a plain string or with a text key now gets a targeted message explaining that axis title text is authored on the chart via `x_label`/`y_label`, instead of a generic "expects a mapping" key dump that omitted the one key the user actually wanted (#8733).

### Performance

- **Board parsing is up to 11x faster:** every YAML parse in `dct`, the render worker, the LSP, and the playground now uses the bundled libyaml C loader instead of PyYAML's pure-Python scanner; a 1000-line board that took 13ms now parses in about 1ms, with identical output and a nesting-depth guard so the faster loader can't be crashed by pathological input (#8835).
- **Board SVG exports contain far less duplicate CSS:** exported dashboard SVGs no longer repeat identical styling text for every markdown, title, and callout element on the board; a 69-tile dashboard dropped 42 duplicate style blocks. Exported files are smaller with no visual change (#8789).
