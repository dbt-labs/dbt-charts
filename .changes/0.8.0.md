## 0.8.0 (2026-09-15)
### Features
- `dct` can point at a dbt project outside the board project: `--dbt-project-dir` on the commands that read a dbt project, the `DBT_PROJECT_DIR` environment variable behind it, and a `dbt_project_dir:` key in `dbt_charts.yml`. The flag wins over the config key, which wins over today's default of the board project directory; a named path that does not exist is an error rather than a silent fallback.
- `dct cloud login` opens the approval page in a browser, the way `gcloud auth login` and `gh auth login` do; the URL is still printed as a fallback. `--no-browser` prints it without opening anything, and `--start` never opens a browser.
### Fixes
- A variable's `min`, `max` or `step` must be a finite number. `.inf` or `.nan` published a bound the control read back as `NaN`, so the board now errors at parse time instead of rendering a control that ignores it.
- A board rendered to SVG, `dct render`'s default format, is a static picture: every interactive rule left the board's embedded stylesheet for the HTML host page. A standalone `.svg`, or a page embedding one without the host stylesheet, no longer draws hover tooltips or hover emphasis, no longer shows a text cursor or selection highlight on chart text, and no longer lets a table row's link be clicked through its own cell values. All of it still works in `--format html` and under `dct serve`; an embedder that wants it back ships `controls_stylesheet()` alongside the SVG.
- Variable controls: a multiselect can be emptied again through its `All` row, a `default: true` checkbox can be unchecked, the slider commits a drag on both track and thumb, an option menu opens under its own field instead of drifting away from it, and a pressed control draws a focus ring.
- A multiselect's option menu stays open while you pick members and reopens after the board re-renders, rather than closing on the first pick.
- List-valued variables are read from and written as repeated URL keys (`?region=west&region=east`); `dct serve` previously kept only the last repeat. Existing JSON-encoded links still resolve.
- A text variable input draws the value you committed immediately, instead of snapping back to the previous one until the render lands. It also follows its field when the page scrolls or resizes and takes the field's own type size, so it no longer shrinks on a scaled board.
- A number variable input honors authored `min`, `max` and `step`, clamping and snapping on commit and passing them to the native spinner. An empty text or number field draws its `placeholder` as a muted hint rather than in the value color.
- Horizontal bar charts with a `support_table` beside their category labels no longer reserve the table's width twice, recovering the plot width that indentation cost.
- The bundled Pygments lexer opens the `queries.<name>: |` SQL shorthand only under a top-level `queries:` key, so a nested mapping of that name is no longer highlighted as SQL.
- A zero baseline rule is no longer painted when the resolved y domain excludes 0. An all-negative line or area chart, or a bar chart with `zero: false` on data far from zero, drew the rule outside the plot rect, which grew the card to several times its slot height (and stretched every sibling card sharing that row) or, on the independent dual-axis path, rendered the chart blank.
- `dct docs error-reference` and `dct docs warning-reference` work on an installed wheel. Both reference documents were excluded from the package build, so every PyPI install answered those two topics with "error-reference.md is missing from the installed package." and its warning-side equivalent.
- A board-level `style.charts.bar.orientation` now reaches its bar charts. Only an inline `style.orientation` on the chart was consulted, so the board default was a silent no-op while its sibling `bar.stack` cascaded normally.
- `dct docs` lists the three generated references (`reference`, `error-reference`, `warning-reference`) in its topic index, and `dct docs all` includes the field reference it already advertised as "unsliced". The reference also documents the `dbt_charts.yml` project-config keys, `execution.max_template_output_bytes` among them. `dct docs all` grows from roughly 68KB to 310KB, worth knowing before loading it into an agent's context.
- Static column attribution no longer gives up on a set operation carrying its own `ORDER BY`. A `UNION` of `ref()` arms with a sort reported `WARN-DBT-QUERY-COLUMNS-INDETERMINATE`, and `dct validate` stopped checking that query's columns against the dbt models; the sort restates output columns the arms already attributed, so the query is checked like any other.
- On a 100%-stacked bar or area chart, an authored percent format is applied to the raw measure value in the hover rows, the printed value labels and the stack total: a count of 20 reads `2000%`, its group total of 80 reads `8000%`. The normalized stack pins its own 0-100% axis, so the format never reaches the axis it was written for. dbt Charts now warns (`WARN-NORMALIZE-PERCENT-FORMAT-READS-RAW-VALUE`) when the measure is not already a 0..1 share; a chart whose stack groups each sum to about 1 is silent, since there the raw value and the painted share are the same number.
- A quantitative axis's ticks below 1 now write out in digits instead of d3's SI sub-unit prefixes, whether the axis has a baked tick ladder or none (a theme leaving `ticks.count` unset, or `multiples.scale: independent`). A y-axis over 0.29-0.38 reads `0.3` / `0.35`, where it used to read `300m` / `350m` and be taken for millions. Ticks at or above 1 keep the axis's own k/M compaction, and any axis with an authored literal `format:` spec or a `style.formats` alias of its own, or a log scale, is unaffected.
- A bar chart's `sort:` orders categories by the sort column's own value rather than by that column's total across the category's rows, so a category holding fewer rows than its neighbors no longer sorts out of place. Sorting a stacked bar by its own measure still orders by the stacked total; a grouped bar sorted by its measure now ranks each category by its smallest series, so sort by a pre-summed column when you want the group total.
- A `support_table` below the plot now clears x labels the chart rotated to fit: the gap is measured from the angle the labels are actually drawn at, rather than assumed to be two lines of horizontal text, so a chart with enough categories to auto-tilt its labels no longer needs `style.support_table.label_max_lines` tuned by hand. Two more cases are covered wherever an authored `labels.angle` pins the tilt: a date axis whose points sit further apart than their own grain (ten dates 45 days apart, say) shows Vega's own date labels (`September`, `2024`) instead of short `1 Jan` labels, and an axis setting `labels.font.case: upper` or `lower` paints its labels in that casing. In both cases the painted text can differ in width from the text the gap was measured against.
- A bar chart with `style.orientation: horizontal` now gets an auto-generated link on its `x` category, like a vertical bar. `x` is always the category or time channel for a bar, never the measure, so orientation no longer suppresses the link.
